# SORAの地上クルー統合

GameTargetの `prototype/road.js` と `prototype/chasecar.js` を2026-09-16の作業ツリーから導入。
SORA側の接続は `prototype/groundCrew.js` に分離している。リポジトリ全体の同期はしない。

- 開発途中版の離陸前チェックボックスで選択。既定は無効。
- 道路・車モジュールと道路タイルは、有効にして離陸した後に読み込む。
- 白は追尾、青はJDGのターゲットまたはPDGの宣言目標付近へ先行する。
- 車の出発地点は離陸時に保存。非同期取得が遅れても気球の現在位置から配置しない。
- 青の100m進入制限は経路の途中形状にも適用。両車はDEM境界から200m内側に留める。
- 道路はz14、周囲2500m、上限64枚。失敗・未取得・上限到達を、道路の断絶と混同しない。
- 各タイル取得には10秒のタイムアウトを設ける。取得失敗で飛行を止めない。
- 無線は問い合わせ時点の報告。既存の気球・風・マーカー物理、PDG採点は変更しない。
- IGCには適用しない。街並み、車内視点、黄色い操作車、回収採点は今回の移植対象外。

## 検証

SORAルートを `python -m http.server 8002 --bind 127.0.0.1` で配信する。
Playwrightが解決できない環境では `SORA_PLAYWRIGHT` にパッケージの絶対パスを指定し、
`node experiments/ground-crew/verify.mjs` を実行する。

既存の検証結果を保持する場合は `SORA_VERIFY_OUT=tmp/final-verification/` のように
出力先を指定できる（SORAルート基準、末尾 `/`）。`SORA_CACHE` は出力先を基準とする
キャッシュディレクトリで、例: `../crew-verification/cache/`。いずれも省略時は従来の配置。

実DEM・実道路・Three.js CDNを使うためネット接続が必要。
試験用フックはHTTP応答にのみ追加し、本体ファイルには埋め込まない。
取得済み公開タイルのキャッシュ・合成IGC・スクリーンショットは非公開の `tmp/` に置く。
IGCの検証用には架空のIGCとZIPをスクリプト自身が生成する。実ログは使わない。

既定、setup、共有エリア、devのJDG/PDG、IGCの見る/飛ぶ/なぞるを確認。
クルーありでは近距離・遠距離・PDG・スマホ相当・道路取得失敗を確認し、
30分ぶんの走行を通じた進入制限・地形境界・有限値と、車の現在地の風の報告を検算する。
実機スマホと公開サイトの確認は別工程。
